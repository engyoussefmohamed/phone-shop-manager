# نظام إدارة محل التلفونات (PSM)

برنامج ديسكتوب لإدارة محل تلفونات: مبيعات، مشتريات، مخزون بتتبع IMEI،
عملاء، موردين، آجل (فلوس ليا/عليا)، موظفين وسلف، مصروفات، خزنة، صيانة،
تقارير، ولوحة تحكم. مبني بـ Python + PySide6، وقاعدة البيانات
**Microsoft SQL Server** مركزية - يعني تقدر تربط أكتر من جهاز/فرع على
نفس القاعدة، وتقدر تفتحها وتشوف كل الجداول من SQL Server Management
Studio (SSMS) عادي.

## 0. قاعدة البيانات: SQL Server + نظام الفروع

- كل بيانات البرنامج متخزنة في قاعدة بيانات SQL Server واحدة (اسمها
  الافتراضي `PhoneShopManager`)، مش في ملف محلي. عشان أكتر من جهاز
  يشتغلوا سوا (أكتر من فرع، أو أكتر من كاشير في نفس الفرع)، كل الأجهزة
  دي لازم تتوصل بنفس السيرفر (نفس الـ IP/اسم السيرفر) وتستخدم نفس اسم
  قاعدة البيانات.
- فيه جدول `branches` (الفروع) مربوط بكل الجداول العملياتية في النظام
  (المخزون، المبيعات، المشتريات، الخزنة، العملاء، الموردين، الديون،
  الصيانة، ...) عن طريق عمود `branch_id`. عزل بيانات كل فرع عن التاني
  بيتعمل تلقائي جوه القاعدة نفسها (Row-Level Security) - يعني الموظف
  بيشوف بيانات فرعه بس، والأدمن يقدر يشوف/يختار يشتغل على أي فرع.
- أول تشغيل للبرنامج هتظهرلك نافذة "إعداد الاتصال بقاعدة البيانات"
  تدخّل فيها: اسم السيرفر (زي `localhost\SQLEXPRESS` أو IP الجهاز اللي
  عليه السيرفر)، اسم قاعدة البيانات، ويوزر/باسورد SQL Server (أو
  Windows Authentication). البرنامج بينشئ القاعدة والجداول تلقائي أول
  مرة.
- لازم يكون عندك SQL Server مثبت على جهاز واحد على الأقل في الشبكة
  (نسخة **SQL Server Express مجانية** كفاية لمحل صغير/متوسط) - نزّلها
  من موقع مايكروسوفت، وفعّل فيها "TCP/IP" من SQL Server Configuration
  Manager عشان الأجهزة التانية تقدر توصلها، وافتح البورت `1433` في
  الفايروول.
- لازم كمان يكون عندك **ODBC Driver 17 أو 18 for SQL Server** مثبت على
  كل جهاز هيشغّل البرنامج (بيتحمّل مجاني من موقع مايكروسوفت).
- ملفات قاعدة البيانات الفعلية (`.mdf`/`.ldf`) بتتحط جوه فولدر `db\` بتاع
  المشروع تلقائي (بدل مكان SQL Server الافتراضي) - ده بيشتغل بس لو
  SQL Server شغال على **نفس الجهاز** اللي فيه مجلد المشروع، لإن اللي
  فعليًا بيكتب الملفات في المسار ده هي خدمة SQL Server نفسها مش
  البرنامج. **لازم تدّي خدمة SQL Server صلاحية كتابة على فولدر `db\`**:
  افتح `services.msc`، دوّر على SQL Server (اسمها غالبًا
  `SQL Server (SQLEXPRESS)`)، شوف اسم الحساب اللي شغالة بيه من تاب
  Log On (غالبًا `NT SERVICE\MSSQL$SQLEXPRESS`)، بعدين من خصائص فولدر
  `db\` > Security > Edit، ضيف الحساب ده وادّيله صلاحية Modify. لو
  القاعدة اتعملت قبل كده في مكان تاني، البرنامج مش هينقلها - امسحها من
  SSMS وشغّل البرنامج تاني عشان تتعمل من الأول في المكان الصح.

## 1. التشغيل لأول مرة (على جهازك للتجربة والتطوير)

```bash
cd phone_shop_manager
python -m venv venv
venv\Scripts\activate        # على ويندوز
pip install -r requirements.txt
python main.py
```

هيظهرلك نافذة إعداد الاتصال بقاعدة البيانات أول تشغيل - دخّل بيانات
سيرفر SQL Server عندك ودوس "اختبار الاتصال" للتأكد، بعدين "حفظ ومتابعة".
البرنامج هينشئ قاعدة البيانات والجداول والفرع الرئيسي تلقائي.

**حسابات الدخول الافتراضية (غيّرها فوراً من الإعدادات > المستخدمين):**
- مدير: `admin` / `admin123` — شايف كل حاجة (الأرباح، أسعار الجملة، الموردين، المشتريات، التقارير، وكل الفروع).
- موظف: `employee` / `emp123` — مربوط بالفرع الرئيسي تلقائي، شايف بس المخزون بسعر البيع، المبيعات، العملاء، الصيانة. مش شايف أسعار الجملة ولا الموردين ولا الأرباح ولا المصروفات ولا الخزنة.

### ترحيل بيانات قديمة من نسخة SQLite

لو عندك نسخة قديمة من البرنامج شغالة بملف `db/shop.db`، استخدم السكريبت
ده مرة واحدة عشان ينقل كل البيانات القديمة لقاعدة SQL Server الجديدة
تحت "الفرع الرئيسي" (لازم يكون عندك إعداد اتصال محفوظ بالفعل، شغّل
البرنامج مرة الأول لو لسه ماعملتش الإعداد):

```bash
python dev_tools/migrate_sqlite_to_mssql.py --sqlite-path "db/shop.db"
```

## 2. هيكل المشروع

```
phone_shop_manager/
  main.py                  # نقطة تشغيل البرنامج
  app/
    database.py             # الاتصال بـ SQL Server، الجداول، RLS للفروع
    db_config.py             # حفظ/تحميل إعدادات الاتصال (db_config.json)
    licensing/               # نظام التجربة والترخيص (اقرأ قسم 4)
    ui/                       # كل شاشات البرنامج
      db_setup_dialog.py       # نافذة إعداد الاتصال بقاعدة البيانات
    utils/                    # عناصر واجهة مشتركة وستايل التطبيق
  dev_tools/                 # أدوات المطوّر فقط - ماتتشحنش مع البرنامج للعميل
    generate_keys.py
    generate_license.py
    migrate_sqlite_to_mssql.py  # ترحيل بيانات قديمة من SQLite
    private_key.pem          # سرّي جداً - يفضل عندك انت بس
  requirements.txt
```

## 3. تحويل البرنامج لملف تشغيل .exe (بعد الانتهاء من التجربة)

```bash
pip install pyinstaller
pyinstaller --noconfirm --onefile --windowed --name "PhoneShopManager" main.py
```

الملف النهائي هيطلع في `dist/PhoneShopManager.exe`. اللي بتوزعه للعميل هو
مجلد `dist/` بس (أو الملف .exe لوحده لو استخدمت `--onefile`) — **متوزّعش
مجلد `dev_tools/` أو ملف `private_key.pem` نهائياً**.

## 4. نظام التجربة والترخيص (الحماية من النسخ)

- أول تشغيل للبرنامج على أي جهاز = فترة تجربة 7 أيام تلقائي، مربوطة
  ببصمة الجهاز نفسه (معالج + قرص + بايوس)، فمينفعش تنسخها بفلاشة لجهاز
  تاني وتتجدد التجربة.
- بعد الـ7 أيام، البرنامج بيوقف ويطلب من العميل يصدّر "ملف طلب ترخيص"
  (من شاشة الإعدادات > الترخيص، أو من شاشة انتهاء التجربة نفسها). الملف
  ده بيتولد تلقائي وفيه اسم المحل والـHWID الكامل بتاع جهازه - العميل
  يبعتهولك واتساب أو إيميل.
- انت تشغل الأمر ده على جهازك، وهو بياخد كل البيانات من الملف تلقائي
  (من غير ما تنسخ HWID طويل يدوي):

```bash
python dev_tools/generate_license.py --request-file "طلب_ترخيص_XXXX.txt" --days 365
```

  - أو لو حابب تدخل البيانات يدوياً: `--hwid <HWID الكامل> --customer "اسم المحل"`.
  - `--days 0` أو من غيرها خالص = ترخيص بدون تاريخ انتهاء.
  - الأمر هيطلعلك ملف `.lic` في `dev_tools/issued_licenses/` — ابعته
    للعميل يستورده من شاشة الإعدادات > الترخيص.
- الترخيص موقّع بمفتاحك الخاص (RSA)، فمينفعش حد يزوّره أو يعدّله من غير
  المفتاح الخاص اللي معاك انت بس.
- عايز نسختين لعميل واحد على جهازين؟ ولّد ترخيصين منفصلين، كل واحد
  بالـ HWID بتاع جهازه.

**تنبيه مهم:** لو ضاع أو اتسرق `private_key.pem`، أي حد يقدر يولّد
تراخيص باسمك. خليه في مكان آمن (مش على نفس الجهاز اللي فيه كود المشروع
المنشور، ومش على الفلاشة اللي بتوزعها).

## 5. نسخ احتياطي

من شاشة الإعدادات > نسخ احتياطي، تقدر تاخد نسخة احتياطية من قاعدة
بيانات SQL Server (`BACKUP DATABASE`) - المسار اللي بتكتبه لازم يكون
مسار موجود على **جهاز السيرفر نفسه**. لو السيرفر شغال على نفس جهاز
المحل فده مش هيفرق معاك. للاسترجاع، استخدم `RESTORE DATABASE` من SQL
Server Management Studio (وقفل البرنامج من على كل الأجهزة الأول).
انصح العميل ياخد نسخة كل فترة، ويحفظها في مكان تاني (فلاشة/كلاود).

## 6. إيه اللي جاهز دلوقتي وإيه اللي ممكن نضيفه بعدين

جاهز: كل الشاشات المتفق عليها، الصلاحيات (مدير/موظف)، دعم أكتر من فرع
على نفس القاعدة (SQL Server + Row-Level Security)، الترخيص والتجربة،
النسخ الاحتياطي.

أفكار لمرحلة تانية لو حبيت: طباعة فواتير PDF مباشرة، باركود سكانر
للـ IMEI بدل الكتابة اليدوية، رسوم بيانية في التقارير، تنبيهات تلقائية
لأقساط الآجل المتأخرة، تقارير مقارنة بين الفروع.
